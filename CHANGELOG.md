# Changelog

All notable changes to placekit are recorded here. The format follows Keep a Changelog, and versions follow Semantic Versioning.

## [Unreleased]

### Added

- Three more README teachings the consumer gauntlet showed missing. The Field masks section now states that search and nearby mask paths carry the `places` prefix while place details mask paths are bare field names, and that a details mask must still name `id` or `name` or the details call raises `DecodeError` even on a well-formed response. The endpoints table row and the Quickstart photo passage now name the `skip_http_redirect` keyword and the `photo_uri` attribute on `PhotoUriResult`, so the photo URI mode can be asked for from the guides alone. The session token paragraph now states that tokens are caller generated and a UUID is the usual shape.
- Three README teachings the consumer gauntlet showed missing. The Addresses section now names the `country_code` reader beside `postal_code` and states its plain string or None return against the `PostalCodeResult` object the postal reader returns, and its worked example starts from a `place_details` call with the warning that the address readers over a bare search result carrying neither address components nor a postal address answer quietly with None readings rather than an error. A new autocomplete passage names the `place_predictions` and `query_predictions` containers and teaches that a prediction's `text` is an optional `FormattedText`, with the display string at `prediction.text.text`, the match ranges at `prediction.text.matches`, and a None guard before the read. A new opening hours example fetches details and checks `current_opening_hours` before printing `current_opening_hours.open_now`, which can itself be None and prints as None, and the `weekday_descriptions` lines, naming the wire spelling `currentOpeningHours` as the same field under its other spelling and teaching that both levels of the path can be None.
- Request parameters that previously could not be expressed, across the board. Text Search gains `page_size`, `min_rating`, `ev_options`, `search_along_route`, `routing_parameters` and the two include booleans. Nearby Search gains `included_primary_types`, `excluded_primary_types`, `routing_parameters` and `include_future_opening_businesses`. Autocomplete gains `origin`, `input_offset`, `included_primary_types`, the three include booleans and an optional `fields` mask.
- `PhotoUriResult`, returned by `place_photo` with `skip_http_redirect=True` instead of following the media redirect, carrying the photo name and its short lived URI.
- `QueryPrediction`, modelled alongside `PlacePrediction` and exposed as `AutocompleteResult.query_predictions`, so query predictions are no longer dropped by the autocomplete surface.
- A lifecycle API on both clients, with `close()`, `with` on `Client` and `async with` on `AsyncClient`. Calls after close raise `ConfigError`.
- Typed response coverage for opening hour periods, address components, plus code, viewport, postal address, primary type display name and current opening hours on `Place`, the flag and maps URIs on `Photo`, the resource name on `PlacePrediction`, and `routing_summaries` on both search results, with `search_uri` carried by the text search result alone.
- Typed opening hours completion on `OpeningHours`, with `next_close_time` and `next_open_time` as unparsed timestamp strings, `special_days` carrying a new `SpecialDay` model, and `secondary_hours_type` naming the kind of a secondary hours entry. `Place` gains `current_secondary_opening_hours` and `regular_secondary_opening_hours` as lists of `OpeningHours`, and both join the Place Details default mask.
- `PostalAddress` completion with `sublocality`, `organization` and `recipients`, so the structured address carries the delivery names the API returns beside the locality fields.
- Nine more typed `Place` fields. `editorial_summary` and `google_maps_type_label` reuse `LocalizedText`, `opening_date` reuses `Date`, and `icon_mask_base_uri`, `icon_background_color`, `utc_offset_minutes`, `pure_service_area_business`, `moved_place` and `moved_place_id` land as scalars whose absence reads None rather than a fabricated value. All nine join the Place Details default mask.
- `Place.reviews` with a new `Review` model reusing `LocalizedText`, `AuthorAttribution` and `Date`, carrying the review text and its original language form, the rating as a float, the author, the publish time and the visit date. Reviews join the Place Details default mask and stay out of the search defaults, whose field tier for them is unchecked.
- The 23 dine, service and amenity flags on `Place`, from `takeout` and `delivery` through `serves_breakfast` to `good_for_watching_sports`, as optional booleans whose absence reads None and never a fabricated false. All 23 join the Place Details default mask.
- Three boolean option objects on `Place` with new `PaymentOptions`, `ParkingOptions` and `AccessibilityOptions` models, every leaf an optional boolean whose absence reads None. The three parents join the Place Details default mask.
- Strict decoding for those optional boolean leaves. A non boolean wire value in one of them raises `DecodeError` instead of being stored verbatim, so a switched off flag can no longer read as on.
- Four wrapper models on `Place`. `TimeZone` types only its id, `GenerativeSummary` and `ReviewSummary` type only their `LocalizedText` payload, and `ConsumerAlert` types its plain string overview and language, with the flag, disclosure, link and detail leaves beside them staying in raw. All four parents join the Place Details default mask.
- `GoogleMapsLinks` and `PriceRange` on `Place`, with a new `Money` model shared with the price range endpoints. Money units decode from the JSON string form the wire uses for int64 values to a real int, and an open ended price range keeps its absent end as None. Both parents join the Place Details default mask.
- The EV charging summary on `Place` as `EvChargeOptions` with `ConnectorAggregation`, typing the connector count, the per type charge rate and counts, and the availability counts with their last update time. The parent joins the Place Details default mask.
- `AddressDescriptor` on `Place` with new `Landmark` and `Area` models, typing the paired resource names and place ids, the display names, the landmark types and distances, and the area containment. The parent joins the Place Details default mask.
- Parsed error envelope details on every API exception, as `error_code`, `details`, `field_violations` and `quota_violations`.
- A configurable response size cap on the Rust core builder, defaulting to 32 MiB. The Python clients expose no setting for it, so the configurability stops at the Rust layer and a Python caller always runs with the default.
- Client side validation for `min_rating`, Nearby Search result counts, session token format, and mutually exclusive location bias and restriction values. Location values are now typed shapes end to end, so a circle in a Text Search restriction fails locally instead of at the API.

- `scripts/check_no_emdash.py`, a codepoint scan that keeps em dashes out of tracked text files.
- Core side validation of request coordinates, circle radii and EV charging rates, so non-finite or out-of-range values fail locally with a configuration error instead of serializing as JSON null or passing to the API unchanged.
- `Retry-After` headers in HTTP date form are read alongside the delta seconds form, with a date in the past meaning retry now.
- A stubtest step in `make check`, running mypy against the shipped type stubs so stub drift fails the gate instead of shipping. The dev extras now carry mypy and maturin on the same pins the build itself uses.
- Version coherence coverage for `Cargo.lock` in `scripts/check_version.py`, with tests that copy the repo layout, mutate one carrier of the version, and watch the guard fail. The guard also accepts prerelease version headings in this changelog.
- A Dependabot configuration proposing weekly updates for the GitHub Actions both workflows use.
- A recorded corpus conformance layer in the test suite, with 41 recorded fixtures and 4 synthesized fixtures excerpted from the live recording sessions, a corpus builder script that regenerates every fixture from its cassette, a coverage manifest and coverage table accounting for all 55 taxonomy cases, and three suites covering recorded conformance, synthesized conformance and corpus accounting.
- Three constants modules carrying the vocabularies callers pass most often, as plain string constants that drop into the existing client slots with no adapter. `placekit.types` holds the place type vocabulary from the official Place Types page (478 Table A values, 36 Table B values, 4 address component only values and the 2 Autocomplete collections), `placekit.lang` holds the 82 supported language codes from the Google Maps Platform FAQ table, and `placekit.ranking` holds the ranking preferences split by method, since Text Search and Nearby Search accept different sets. The modules are vocabularies only. The type and language slots keep accepting any string as far as vocabulary goes, including values this version has never heard of, while the ranking slots form a closed set and refuse an unknown value locally with a `ConfigError` naming the values the endpoint accepts. A string carrying control characters or unpaired surrogates is refused locally in every slot.
- A `placekit.address` helper module over the typed models, with component lookup by type, country and postal code extraction across the component and postal carrier sets, district resolution, presence flags, compound plus code splitting and postal address field readers. City resolution returns its value with the carrier it came from and a confidence grade in the open, because which carrier holds the city changes by country and the carriers sometimes disagree on the same place. Stated answers ship for Japan and the United Arab Emirates as precedences and for the United Kingdom as a contested two value answer, each scoped to the sampled locality it rests on, and every other country follows a generic fallback chain capped at the heuristic grade. Caller argument errors in the module raise `ConfigError`. The module ships no prefix or suffix postal assembly and no sorting code reader and no formatting, because the recorded corpus holds no instance those surfaces could rest on.
- Object arguments for the two calls migrants reach for after a search. `Client.place_details` and `AsyncClient.place_details` now accept a `Place` or a `PlacePrediction` as well as a place id string, returning a new `Place`, and an object carrying no id fails locally with the field mask named as the cause. `Client.place_photo` and `AsyncClient.place_photo` now accept a `Photo` as well as a photo name, and a `Photo` passed with neither size argument defaults one size from the photo itself, its native width capped at 4800 or its height when it carries no width.
- The attribute reading contract is now documented in the models and field mask documentation. An attribute the response did not carry reads None, an empty list, or its empty default, never an error and never a fabricated value, and raw membership by wire name is the supported way to tell carried fields from unreturned ones.
- A migration guide at MIGRATING.md walks python-google-places users across to placekit through the four canonical legacy examples, each executed against the offline stub, with the name and constants mapping, the attribute reading contract, and the removed endpoints named as removals.

The caller's own Geocoding API call comes first, with the v4 generation named as current, the enablement and key restriction steps stated before the code, and its dated price. The autocomplete and details crossing follows on shipped surface at its per lookup price, and the one call text search crossing closes the section with its Pro tier price and its place semantics warning at full strength. The geocode boundary itself stands, and the crossings are calls a caller performs, not a client feature.
- A normalization guide at NORMALIZATION.md teaches the address handling the recorded fixture corpus and placekit.address embody, with an oddities catalogue of the shapes the corpus actually returned, per country readings that state their evidence and its reach, the decision rules the module's grades and carriers rest on, worked recipes that run against the recorded fixtures, and the list of things the module cannot promise. A proof suite at tests/test_normalization_guide.py executes the guide's examples against the fixtures and pins its boundary sentences as text, so a later edit cannot quietly soften them away.
- A vulnerability scanning workflow for the locked Rust tree. A weekly scheduled run and any change to `Cargo.lock` audit the tree through cargo audit, and Dependabot now proposes weekly updates for the Rust and Python dependencies alongside the GitHub Actions pins, so a published advisory against the runtime surface produces a scan result and an update proposal instead of waiting on a human to notice.

### Changed

- **Breaking.** `raw` is now the response body itself, on every model the client returns. The Rust core returns the body beside the typed value and Python builds raw from it, so a wire name is a key in raw exactly when the response carried that field, with no reserialization in between. Explicit nulls, explicitly empty lists, empty strings and zero valued fields now keep their keys in raw, and fabricated values are gone from it, so a location the wire sent with a latitude alone no longer claims a longitude in raw. Callers who compare raw between responses, snapshot it into golden files or branch on raw membership will see those keys appear and the fabricated ones disappear on the same wire data. In the same change, two payload shapes that used to kill a whole response now decode the way the model layer has always decoded them. A null in a plain string position reads None in the attribute, and a null element inside a modelled string list reads None at its wire index. An explicit null where a list or a number belongs still raises `DecodeError`, under the standing contract that a null is not a synonym for absence, but the error now comes from the Python decoder, naming the model and the key where the position has a decoder form and the generic conversion form where it does not, and it carries the HTTP status of the response it arrived on. A null place id on an autocomplete prediction now surfaces one call later, as a `ConfigError` from the details resolver, instead of failing the autocomplete call itself. A result raw that carries one of the still refused nulls can no longer be fed back through `from_api`, whose decoder applies the same contract to it.
- **Breaking.** StringMatch offsets are now optional. A match the API returned without a start or end offset now reports None for that offset instead of a fabricated 0, so an absent offset and a sent 0 are distinguishable again. Callers who need the old behaviour can write match.start_offset or 0. In the same release, every model class that decodes from a JSON object now carries that object on a raw attribute, matching the behaviour Place and the result classes always had. Constructor signatures gain the raw parameter last, with a default, and match args gain raw last.
- Because every raw is a deep copy of its payload, a decoded result now holds its response payload about twice over, once across the typed fields and once across the raw attributes.
- **Breaking.** Search result `routing_summaries` are typed `RoutingSummary` objects with `Leg` entries instead of untyped dicts, on both text and nearby results. The dict form stays reachable unchanged through the result level `raw`, so no response data is lost in the change.
- A circle in a Text Search location restriction now raises `ConfigError`, the same type as the other local validations, instead of a bare `ValueError` outside the exception hierarchy.
- Client construction and `FieldMask` raise `ConfigError` for empty keys, invalid timeouts and invalid mask paths instead of bare `ValueError`, so every local misuse has the one documented type.
- Default field masks now include the place resource name on each endpoint that carries a default, and the README and fields docs state plainly that the defaults reach the Enterprise billing tier.
- Header construction fails loudly on a value that cannot be sent instead of silently dropping the header, and an API key that cannot be a header value is rejected when the client is built.
- The offline test stub now honours field masks, returns autocomplete distances only for requests with an origin, and serves photos through a redirect, so the suite asserts the behaviour the real API actually has.

- Release wheels now build on native arm runners (ubuntu-24.04-arm, macos-15) instead of cross runners, with Linux wheels pinned to manylinux 2_28, and the publish job checks the tag against the manifests before uploading to PyPI through trusted publishing.
- The macOS arm64 wheel build and test legs moved from macos-14 to macos-15, after GitHub retired the macos-14 image those legs were pinned to, so the release legs still start on tag day.
- The version guard now refuses the publish path while this changelog's Unreleased section still holds entries, when no release heading exists for the target version, or when a release heading is duplicated, and it ignores headings inside fenced code blocks when it reads the changelog.
- Release wheel builds now remap compiler paths, so the native module inside a released wheel no longer embeds the build machine directory layout in the source paths its panic locations record.
- The release build tool is pinned exactly. The wheels workflow now sets the maturin version on every build action call, at the same 1.15.0 the test legs and the dev environment carry, instead of resolving whatever version the action defaults to on the day the tag is pushed. The two rust-toolchain pin comments now describe their SHA as the master branch tip it is, since that action publishes branch refs rather than versioned releases.
- The dev extras now pin the gate tools exactly, at pytest 9.2.0, mypy 2.4.1 and maturin 1.15.0, the versions the gate environment runs. They previously declared floors, so CI and a local venv each resolved the newest satisfying release at run time and an unreviewed tool release could enter the gate, stubtest included, with no diff in this repo. A tool bump now arrives as a deliberate edit to the pins, in the dev extra and the workflow legs together.
- The source distribution now carries rust-toolchain.toml, so a build from the sdist selects the pinned Rust toolchain rather than whatever toolchain the machine defaults to.
- The package metadata no longer carries a Documentation project URL that repeated the Homepage address.
- Client construction validates the base URL. A base URL carrying a query string or a fragment, or one whose scheme is not http or https, fails at build time instead of silently rerouting every request, while path prefixes keep working and dot segments can no longer escape the configured prefix.
- Client construction also rejects a base URL carrying embedded credentials, which used to become an Authorization header sent to the API host on every request without the caller seeing it.
- The Rust core no longer follows redirects automatically, so the API key header can never be resent to a redirect target. Photo media redirects are followed manually with the API key attached to the first request only.
- Field masks remove duplicate paths rather than rejecting them, reject empty segments, wildcard segments and non-ASCII characters, and are bounded at 100 paths and a 4096 character header value.
- The native module rejects timeout values above one hour, the same cap the Python clients document, instead of only the Python layer enforcing it.
- Errors from the Rust core keep their underlying transport or decode cause as a typed source instead of flattening it into message prose.
- Decoded response values are passed through without clamping or range checks, a deliberate posture now stated in the core documentation. The client is a transport and does not hide what the API returned, and request values the caller controls are validated before sending instead.
- The dev profile keeps only line-table debug info, so incremental `maturin develop` builds stay fast, and the release profile is unchanged.
- **Breaking.** Response models are now frozen dataclasses, matching `FieldMask`, and each model's `raw` is a deep copy of its payload, excluded from repr and equality, so a shared result cannot be rebound field by field and results compare on their modelled fields. The freeze is shallow, and list fields and the raw payload stay mutable in place. `LatLng` is hashable.
- The default Place Details field mask now requests every modelled field, so a default `place_details` call populates address components, plus code, viewport, postal address and current opening hours instead of leaving them permanently empty, while the search defaults remain a curated subset.
- Printing a `PlacesError` now shows the context the type collects (the failed call, the status code, the Google status and the retry delay) alongside the message.
- `Place.opening_hours` gains the alias `Place.regular_opening_hours`, matching its wire name.
- The README now leads with the prebuilt wheel install story, and building from source stands as a full section near the top.
- **Breaking.** Text Search drops its duplicate `max_results` parameter, leaving `page_size` as the one spelling for that endpoint. Nearby Search keeps `max_results`, which maps to its own endpoint's `maxResultCount` field. Passing `max_results` to `text_search` now raises a plain `TypeError`, like any unknown keyword.
- Every GitHub Action in both workflows is pinned to a commit SHA with the resolved version in a trailing comment, including the PyPI publish action, which previously tracked a moving branch. The workflows declare per-job permissions and no longer persist checkout credentials.
- Release builds no longer target the retired macos-13 runner image, which had left the macOS Intel wheel leg unable to start, and the macOS legs now pin their deployment targets, 10.12 for Intel and 11.0 for Apple silicon.
- Publishing is gated on an install matrix that installs and imports every built wheel on its own platform plus the sdist, with a Python 3.10 leg exercising the abi3 floor, and every test install is hermetic, so a job can never silently test the published package instead of the artifact it just built. The publish job runs only on version tag pushes, the tag pattern accepts version tags only, and a publish in flight is never cancelled by a re-run.
- The declared Rust floor is 1.88, the oldest toolchain that compiles the locked dependency set, up from a declared 1.74 that the locked dependencies no longer support. The pin lives in a new `rust-toolchain.toml` and in CI, and Cargo and maturin invocations in the gate and the workflows now run with `--locked` wherever the flag is accepted.
- Package metadata uses the SPDX license expression form, carries project URLs, Python classifiers for 3.10 through 3.14 and the operating system classifiers for MacOS, Windows and POSIX Linux, matching the wheel platforms, and aligns the keyword list with the Cargo metadata.
- The source distribution no longer ships the CI configuration under `.github`.
- **Breaking.** A plain http `base_url` is refused unless the parsed host is loopback. Both key forms, the header and the photo key query, travel over the base connection, and plaintext exposed them to anyone on the path to a network host. Loopback bases keep working because that is the documented local stub shape, and classification reads the parsed host, so a hex or decimal IPv4 spelling is judged as the loopback address it canonicalises to.
- **Breaking.** Photo media redirects are screened before each hop is followed. A target carrying userinfo is refused, an https target naming a loopback host the base does not share or a private, link local or unspecified IP literal is refused, and a plain http target is followed only from a loopback base to a loopback target. A media response can no longer steer the client at internal network addresses or downgrade it to plaintext.
- **Breaking.** Photo bodies are accepted only in the image formats the client verifies by signature, JPEG, PNG, GIF and WebP. Every other declared type is refused as a decode error, including `image/svg+xml`, an XML format that can carry script, which previously passed unchecked.
- **Breaking.** An error response whose body is not a Google error envelope no longer has its body quoted in the exception message. The message carries the HTTP status and the body size instead. Envelope errors keep their parsed message and attributes unchanged.
- The concurrency and lifecycle contract is now stated in the README and in both client docstrings. Sharing one client across threads, tasks and event loops is a documented promise, the close docstring now says plainly that closing gates later calls and neither cancels nor waits for in flight work, and the pooling posture, the process lifetime runtime, the cancellation behaviour and the limits on sharing results and on subinterpreters are written down where callers can find them.
- **Breaking.** Every iterable a caller hands to a client method is now materialised under a bound before any request is built. Where the API documentation the client already states gives a slot a maximum, that maximum is the bound, so Autocomplete primary types stop at 5 and the Nearby Search type filters stop at 50, and an Autocomplete collection such as `(cities)` may appear only as the sole primary type value, as the types documentation has always stated. Every other slot falls under one named universal ceiling of 1000 items, shared by the field mask builder and the request body walk. An endless iterable now refuses promptly with a `ConfigError` on both clients instead of hanging the call, an iterable that raises while it is being read surfaces as a `ConfigError` with the original exception chained, and a list longer than its bound raises `ConfigError` before any request instead of travelling to the API to be refused there.
- **Breaking.** Argument validation on the direct argument methods now matches the body methods. A non-string place id, language, region or session token passed to `place_details` raises `ConfigError` instead of escaping the native conversion as a bare `TypeError`, and the same holds for the photo name on `place_photo`. Language and region codes and their kin refuse control characters and unpaired surrogates at the Python layer with a `ConfigError`, instead of reaching the wire percent encoded or escaping as a bare `UnicodeEncodeError`, and a caller object whose own methods raise while its arguments are being validated or materialised now surfaces as a `ConfigError` with the original exception chained instead of the bare builtin it raised.
- **Breaking.** The model conversion layer now validates the scalar types it declares. A fractional number in an integer typed position raises `DecodeError` instead of being silently truncated, through the client and in the direct `from_api` layer alike, while exactly integral floats and the digit strings the wire itself sends still decode normally. A wrong JSON type in a declared string slot raises `DecodeError` instead of being stored verbatim, and direct `from_api` misuse that used to escape as a bare `AttributeError` or `TypeError`, including a mapping handed to a string list slot being read as its own keys, now surfaces as a `DecodeError` naming the model and the key, with payload nesting past a stated depth guard refusing as a `DecodeError` instead of a bare `RecursionError`. The standing null settlements are unchanged by this. A null in a string position still reads None, and a null element inside a modelled string list still reads None at its wire index.
- **Breaking.** The refusals above are complete at their edges. A caller mapping whose item stream cycles over keys it already yielded now counts against the materialisation ceiling by items consumed and refuses with `ConfigError` instead of hanging the call. A fractional `Decimal` or `Fraction` in an integer typed position refuses with `DecodeError` the way a fractional float already did, and a huge integer in a float position on the direct `from_api` layer refuses with `DecodeError` instead of escaping as a bare `OverflowError`. Payload objects that misbehave through the standard protocols, a values or iteration method that raises or a conversion that raises, surface as `DecodeError` on the model layer the way caller objects already did as `ConfigError` on the client, and `BaseException` subclasses still pass through every guard untouched. The items of the code carrying list slots, region codes and the type filters and price levels, pass the same control character and lone surrogate validation as the scalar code strings. A malformed hand built address component, one whose types value is not a list or a plain mapping standing in the components list, raises `ConfigError` from `placekit.address` instead of a bare `TypeError` or `AttributeError`.
- **Breaking.** Error envelope classification no longer depends on the whole response body parsing. An envelope whose body runs past the error body read cap, or that carries a value nested past the JSON parser depth limit anywhere in the body, used to lose its Google status, its message and its error code and fall back to the bare HTTP class, so a quota error on an HTTP 400 arrived as a plain API error and an invalid argument error on an HTTP 429 arrived as a rate limit. The core now recovers the envelope head fields with a tolerant scan whenever the whole document parse fails, and classification follows the envelope in those cases, with the details reading empty when they cannot be parsed. Well formed bodies under the cap behave exactly as before. The same change maps the `OUT_OF_RANGE` status to the invalid request class directly, so that class no longer depends on the response arriving on its canonical HTTP 400 pairing.
- **Breaking.** A non finite number in a payload float position now raises `DecodeError` naming the model and the key, through the client and in the direct `from_api` layer alike. An infinite or NaN latitude used to decode until the `LatLng` construction check refused it with a `ConfigError`, a caller misuse type, so a malformed payload escaped the decoder contract as the wrong exception. Every float slot now honours the contract, coordinates and ratings and distances alike. Building a `LatLng` by hand with a non finite value still raises `ConfigError`, because that is caller misuse rather than a payload.
- **Breaking.** A timeout anywhere in a call now surfaces as a `NetworkError` naming the timeout, including a timeout that fires while an error body is still streaming, which used to arrive as the bare HTTP class with an unreadable body note and no timeout token in any attribute. Timeout originated network errors also report `retryable` as true, matching the documented meaning of the flag. Other network errors keep their existing retryable readings.
- The remaining scalar request slots now validate in Python the way their neighbours already did. `page_token`, `rank_preference` on both search methods, `included_type` and the Autocomplete `session_token` pass through the code string validator, so a wrong type or an unpaired surrogate raises `ConfigError` naming the argument instead of failing inside the native conversion, and unpaired surrogates in the free text arguments raise `ConfigError` naming the argument instead of escaping as a codec error. No vocabulary validation was added, and the client keeps accepting any code string in these slots.
- API exceptions no longer chain the native core exception as their cause. Every native attribute is already copied onto the Python exception, so tracebacks now show the one exception a caller actually catches instead of rendering the same message twice, once under the private native class name.
- `PlacesError` construction normalises `retry_after` the rest of the way. A bool or a non numeric value now reads as None instead of passing through untouched, so the stored value is always a float or None.
- Address helper failures and field mask construction failures now carry context. An exception from a `placekit.address` helper names the helper in its context, and a `FieldMask` construction failure carries the mask as its context, matching the README statement of which surfaces carry context. Model decode errors carry no context of their own and name the model and the key in the message instead, and a client call attaches its context to them as it does to every error it raises.
- String values inside parsed error details are now capped at 500 characters, the same bound the error message has always had, on every envelope path. A details entry of 100000 characters no longer reaches the exception whole.
- The core configuration error rendering drops its fixed prefix and carries the specific message alone, and an error headline no longer renders an empty gap or a duplicated HTTP status when the response carried no Google status.

- Response decoding now pays for copies only where a copy carries an invariant. Through a client call the model layer reads the typed value the bindings built for that call in place instead of deep copying it at every model node, adopts the parsed body as the top level raw instead of copying it, and copies raw once per node below the top, which is the copy that keeps one node's raw independent of every other node's. The direct `from_api` layer makes one copy of a payload per node where it used to make two for every node below the first. No result changes. Raw at every level still deep equals the wire subtree, a result still shares no mutable state with the caller's dict or with any other node's raw, and new tests pin the isolation in both directions on both layers beside a census that holds the decode to one deep copy per node. In the same change, `placekit.address` validates and scans a place's components once per public call and shares that work across every reading the call composes, where one `address_flags` call used to revalidate the same list seventeen times over.
- **Breaking.** The typed layer no longer fabricates coordinate values the wire did not send. A location carrying only a latitude used to expose a longitude of 0.0 in the typed result while `raw` beside it carried no longitude, an empty location object used to read as a place at the zero coordinate point, and a viewport missing a corner used to expose that corner as a `LatLng` of 0.0 and 0.0. The core now carries absence through the typed dict it hands Python, so those bodies behave like their explicit null counterparts: a partial location or a viewport missing a corner raises `DecodeError` naming the missing key, and an empty location object reads as no location, exactly as a null location does. - **Breaking.** The `PlacesError` constructor no longer copies its three list arguments through a bare `list` call. A list argument whose iteration raised escaped construction as the caller's own exception, and an endless iterable was consumed forever, so the three copies were the one unguarded and unbounded caller iterable read left in the library. A plain list or tuple is already materialised in full, so it is still copied directly, under a guard that surfaces any failure as a chained `ConfigError` and with no ceiling, which keeps the wire details arrays the library itself passes whole at any length. Any other iterable is materialised through the shared bounded read the wire facing surfaces use, so one that raises surfaces as a chained `ConfigError`, and one that runs past the ceiling of 1000 items is refused with a `ConfigError` naming the bound. A construction that handed the constructor an endless or over long generator, or a value whose iteration raises, previously hung, escaped bare, or was accepted, and is now refused inside the exception hierarchy.
- **Breaking.** An error whose details payload the bindings cannot convert no longer loses its classification. An integer literal past the interpreter limit for exact conversion (4300 digits) inside the details made the conversion of the payload fail, and that failure demoted the whole error to the plainest `PlacesError`, which the Python layer then read as an `ApiError` with no Google status, no error code and no retryable flag. The details surface, the parsed details and the field and quota views taken together, now degrades to empty for that call instead, and the class, Google status, error code and retryable flag stand exactly as the core classified them. A caller who caught the demoted `ApiError` for such a body now catches the classified error with an empty details surface.
- **Breaking.** Error details are now recovered entry by entry when a body defeats the strict parse. A lone surrogate escape anywhere in the body used to cost the whole details array on the tolerant head scan route, whether it sat inside one entry, where a single string was the whole cause, or in the status or code field outside the details entirely. The scan now reads the array from its own span of the body and parses each entry on its own, so a refused entry degrades alone, clean siblings survive with the field and quota views reading them, a poisoned head field costs the array nothing, and the envelope string cap applies to recovered entries as it does on the whole parse route. The whole array still degrades to empty when the array container itself is unreadable in the text, a cut off array being the standing shape. A body that read with empty details on this route now reads with the recovered entries.
- **Breaking.** A corrupt gzip error body on the core decode route no longer claims a cap stop that never happened. When the whole compressed body had arrived and its stream failed after yielding output, the failure was read as a capped read and the message reported that the read stopped at the 262144 byte cap. Such a body is now reported unreadable, the same construction the transport route gives the same body under the exact lowercase declaration, while a stream that fails on a genuinely capped raw read keeps the capped reading, because there the failure is the cut. The exception class is unchanged for the anchor shape and for genuinely capped reads. One sub shape does change class, a checksum failed stream whose decompressed partial happened to carry a complete envelope was previously classified by that unverified partial, and such a body now falls back to the bare HTTP classification, the same fallback the transport route always gave it.
- **Breaking.** `field_violations` no longer fabricates entries for malformed violation values. The view used to emit one dict of two strings per wire entry, replacing any non string member with the empty string, so a malformed entry read exactly like a genuine empty violation and its sent values were lost. A well formed entry, an object whose `field` and `description` members are both strings, still reads as the same dict of the two strings, byte for byte. Every other entry now reads exactly as the wire carried it, a non object entry as itself and an object with a missing or non string member as the whole object, so nothing in the view is invented and a genuine empty violation is distinguishable from a malformed entry again. The view length still equals the number of entries in the wire array, and the `details` attribute beside it is unchanged, as is the `quota_violations` view.
- A field mask member whose hash, equality or comparison raises can no longer escape standalone mask construction as a bare builtin. The constructor dedupe and the set sort inside `FieldMask.of` read the members once more past the guarded path check, and those reads now sit inside the same typed discipline, so the constructor, `FieldMask.of` and the raw iterable door of `normalize_fields` refuse such a member as a chained `ConfigError`. Well formed members behave exactly as before.
- A `retry_after` value that the `PlacesError` constructor admits but cannot convert no longer escapes construction bare. An int too large to convert to a float raised `OverflowError`, and a numeric subclass whose conversion raises let its own exception out. A conversion failure now reads as None, on the same terms as a bool or a non numeric value, so the stored value is a float or None as the constructor promises.
- A panic inside the stored form conversion of an async call can no longer leave the call unsettled. The conversion runs inside the spawned task after the panic guard over the core future returns, so a panic there would have unwound the task before the completion slot was written or the done flag set, and the Python layer would have polled the handle until the caller cancelled. The conversion now runs under the same panic guard discipline as the core future, and a panic settles the call with the same network class error a guarded core panic produces. No input the shipped response types can produce panics in the conversion, whose failure mode is a returned error, so no caller visible behaviour changes.
- The corpus accounting suite now guards the two blind spots its own machinery carried. The observation linkage is asserted at the same strength as the case linkage, so each observation test must name every fixture its observation claims, its own fixture and its host fixtures alike. Both linkage proofs require the fixture name to reach one of the recorded corpus module loading helper calls in the test, as the literal argument of the call or through a local name bound to the literal, so a fixture name resting in a comment, a docstring, or an assignment no loading call consumes satisfies neither proof. A second guard pins the fixture builder spec list against the coverage manifest recorded set, file for file, with each spec agreeing with its manifest entry on session, exchange and selector place ids. An observation test repointed at another fixture, or a fixture dropped from the builder spec list, now fails the suite instead of silently narrowing the proofs the corpus rests on. No fixture bytes and no library behaviour change.
- A hostile caller value can no longer escape the exception hierarchy at three more doors. The free text arguments of text search and autocomplete are checked inside the guarded argument phase, client construction reads the API key and the timeout under guard including the reads inside its own refusal messages, and field mask member validation is guarded, so a string subclass whose methods raise now lands as a chained `ConfigError` everywhere instead of a bare `RuntimeError`. A fabricated `FieldMask` whose paths state was replaced after construction is refused by `normalize_fields` as a `ConfigError` before any native call, where a missing paths attribute previously raised `AttributeError` and a non string member escaped as a conversion `TypeError` from the native layer. Ordinary values behave exactly as before.
- The tolerant envelope head scan now tracks the whole parse on three more body shapes. A later error value that is not an object clears an envelope an earlier error key found, matching the last wins reading of the parse. A malformed head field costs that field only, so a valid status behind a malformed code token and a valid code and message behind a broken status string still classify the error. An envelope behind a sibling container that never closes is recovered by one bounded recovery pass instead of the body falling back to the bare HTTP class. Bodies that defeated the parse in all three shapes previously classified by HTTP status alone.
- A gzip error body is no longer invisible when its Content-Encoding header names the encoding loosely. The transport decodes only the exact lowercase token, so the case variants and the list forms reached the parser still compressed. The core now decodes those bodies itself, once and under the read cap, on the JSON paths and the photo path alike, so their envelopes classify by Google status. A twice compressed body declared once keeps its previous behaviour, and other encodings are untouched.
- A process that used the AsyncClient could crash while the interpreter exited, with an abort or a segfault after every result had already been delivered correctly. The cause was the completion machinery of the async bridge the bindings built on, whose per call tasks finished each call from a runtime worker thread and were still entangled with the interpreter while finalization dismantled it. Async calls now run through a call handle owned by the bindings that completes into Rust state only, and the Python layer collects each result from its own event loop thread. No public API or result changes. The one cost is completion latency, because a result is delivered on the next pump poll after it lands, sub-millisecond in the common case and at most one settled 4 ms poll interval plus loop scheduling in the worst case. Completion polling and result conversion also run on the caller's event loop thread, so an async call spends more CPU on the calling thread than the retired bridge design did, measured at this head as an increase of 68 to 219 percent in calling thread CPU against the pre repair baseline, varying by method, while still spending less than the synchronous client on every method. Standing subprocess tests pin the exit shapes that used to crash.
- A Tokio runtime failure can no longer escape as a panic outside the exception hierarchy. When the operating system refuses the runtime build or its worker launch (thread or memory exhaustion), the first affected call now raises `NetworkError` naming the refusal or the panic payload, on both clients, instead of a `pyo3_runtime.PanicException` with no result. Panics raised while the runtime drives a call are converted the same way.

The fixture now carries the single object and the pin reads it as one. No library behaviour changes.
