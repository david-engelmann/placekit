# Changelog

All notable changes to placekit are recorded here. The format follows Keep a Changelog, and versions follow Semantic Versioning.

## [Unreleased]

### Added

- Request parameters that previously could not be expressed, across the board. Text Search gains `page_size`, `min_rating`, `ev_options`, `search_along_route`, `routing_parameters` and the two include booleans. Nearby Search gains `included_primary_types`, `excluded_primary_types`, `routing_parameters` and `include_future_opening_businesses`. Autocomplete gains `origin`, `input_offset`, `included_primary_types`, the two include booleans and an optional `fields` mask.
- `PhotoUriResult`, returned by `place_photo` with `skip_http_redirect=True` instead of following the media redirect, carrying the photo name and its short lived URI.
- `QueryPrediction`, modelled alongside `PlacePrediction` and exposed as `AutocompleteResult.query_predictions`, so query predictions are no longer dropped by the autocomplete surface.
- A lifecycle API on both clients, with `close()`, `with` on `Client` and `async with` on `AsyncClient`. Calls after close raise `ConfigError`.
- Typed response coverage for opening hour periods, address components, plus code, viewport, postal address, primary type display name and current opening hours on `Place`, the flag and maps URIs on `Photo`, the resource name on `PlacePrediction`, and `search_uri` plus `routing_summaries` on the search results.
- Typed opening hours completion on `OpeningHours`, with `next_close_time` and `next_open_time` as unparsed timestamp strings, `special_days` carrying a new `SpecialDay` model, and `secondary_hours_type` naming the kind of a secondary hours entry. `Place` gains `current_secondary_opening_hours` and `regular_secondary_opening_hours` as lists of `OpeningHours`, and both join the Place Details default mask.
- `PostalAddress` completion with `sublocality`, `organization` and `recipients`, so the structured address carries the delivery names the API returns beside the locality fields.
- Nine more typed `Place` fields. `editorial_summary` and `google_maps_type_label` reuse `LocalizedText`, `opening_date` reuses `Date`, and `icon_mask_base_uri`, `icon_background_color`, `utc_offset_minutes`, `pure_service_area_business`, `moved_place` and `moved_place_id` land as scalars whose absence reads None rather than a fabricated value. All nine join the Place Details default mask.
- `Place.reviews` with a new `Review` model reusing `LocalizedText`, `AuthorAttribution` and `Date`, carrying the review text and its original language form, the rating as a float, the author, the publish time and the visit date. Reviews join the Place Details default mask and stay out of the search defaults, whose field tier for them is unchecked.
- The 23 dine, service and amenity flags on `Place`, from `takeout` and `delivery` through `serves_breakfast` to `good_for_watching_sports`, as optional booleans whose absence reads None and never a fabricated false. All 23 join the Place Details default mask.
- Three boolean option objects on `Place` with new `PaymentOptions`, `ParkingOptions` and `AccessibilityOptions` models, every leaf an optional boolean whose absence reads None. The three parents join the Place Details default mask.
- Strict decoding for those optional boolean leaves. A non boolean wire value in one of them raises `DecodeError` instead of being stored verbatim, so a switched off flag can no longer read as on.
- Four wrapper models on `Place`. `TimeZone` types only its id, `GenerativeSummary` and `ReviewSummary` type only their `LocalizedText` payload, and `ConsumerAlert` types its plain string overview and language, with the flag, disclosure, link and detail leaves beside them staying in raw. All four parents join the Place Details default mask.
- `GoogleMapsLinks` and `PriceRange` on `Place`, with a new `Money` model shared with the price range endpoints. Money units decode from the JSON string form the wire uses for int64 values to a real int, and an open ended price range keeps its absent end as None. Both parents join the Place Details default mask.
- The EV charging summary on `Place` as `EvChargeOptions` with `ConnectorAggregation`, typing the connector count, the per type charge rate and counts, and the availability counts with their last update time. The parent joins the Place Details default mask.
- `AddressDescriptor` on `Place` with new `Landmark` and `Area` models, typing the paired resource names and place ids, the display names, the landmark types and distances, and the area containment. The parent joins the Place Details default mask.
- Parsed error envelope details on every API exception, as `error_code`, `details`, `field_violations` and `quota_violations`.
- A configurable response size cap on the Rust core builder, defaulting to 32 MiB.
- Client side validation for `min_rating`, Nearby Search result counts, session token format, and mutually exclusive location bias and restriction values. Location values are now typed shapes end to end, so a circle in a Text Search restriction fails locally instead of at the API.
- `make check`, one gate for the whole repo (rustfmt, clippy, Rust tests, version coherence, em dash scan, Python tests), with a CI workflow that runs it word for word.
- `scripts/check_version.py`, which fails unless the version agrees across the Cargo manifests, the changelog, and the Python package, and doubles as the release tag guard in the publish workflow.
- `scripts/check_no_emdash.py`, a codepoint scan that keeps em dashes out of tracked text files.
- Core side validation of request coordinates, circle radii and EV charging rates, so non-finite or out-of-range values fail locally with a configuration error instead of serializing as JSON null or passing to the API unchanged.
- `Retry-After` headers in HTTP date form are read alongside the delta seconds form, with a date in the past meaning retry now.
- A stubtest step in `make check`, running mypy against the shipped type stubs so stub drift fails the gate instead of shipping. The dev extras now carry mypy and maturin on the same pins the build itself uses.
- Version coherence coverage for `Cargo.lock` in `scripts/check_version.py`, with tests that copy the repo layout, mutate one carrier of the version, and watch the guard fail. The guard also accepts prerelease version headings in this changelog.
- A Dependabot configuration proposing weekly updates for the GitHub Actions both workflows use.
- Three constants modules carrying the vocabularies callers pass most often, as plain string constants that drop into the existing client slots with no adapter. `placekit.types` holds the place type vocabulary from the official Place Types page (478 Table A values, 36 Table B values, 4 address component only values and the 2 Autocomplete collections), `placekit.lang` holds the 82 supported language codes from the Google Maps Platform FAQ table, and `placekit.ranking` holds the ranking preferences split by method, since Text Search and Nearby Search accept different sets. The modules are vocabularies only. The client keeps accepting any string in the slots they describe, including values this version has never heard of.
- Object arguments for the two calls migrants reach for after a search. `Client.place_details` and `AsyncClient.place_details` now accept a `Place` or a `PlacePrediction` as well as a place id string, returning a new `Place`, and an object carrying no id fails locally with the field mask named as the cause. `Client.place_photo` and `AsyncClient.place_photo` now accept a `Photo` as well as a photo name, and a `Photo` passed with neither size argument defaults one size from the photo itself, its native width capped at 4800 or its height when it carries no width.
- The attribute reading contract is now documented in the models and field mask documentation. An attribute the response did not carry reads None, an empty list, or its empty default, never an error and never a fabricated value, and raw membership by wire name is the supported way to tell carried fields from unreturned ones, subject to the reserialization limit the models documentation records.

### Changed

- **Breaking.** StringMatch offsets are now optional. A match the API returned without a start or end offset now reports None for that offset instead of a fabricated 0, so an absent offset and a sent 0 are distinguishable again. Callers who need the old behaviour can write match.start_offset or 0. In the same release, every model class that decodes from a JSON object now carries that object on a raw attribute, matching the behaviour Place and the result classes always had. Constructor signatures gain the raw parameter last, with a default, and match args gain raw last.
- Because every raw is a deep copy of its payload, a decoded result now holds its response payload about twice over, once across the typed fields and once across the raw attributes.
- **Breaking.** Search result `routing_summaries` are typed `RoutingSummary` objects with `Leg` entries instead of untyped dicts, on both text and nearby results. The dict form stays reachable unchanged through the result level `raw`, so no response data is lost in the change.
- A circle in a Text Search location restriction now raises `ConfigError`, the same type as the other local validations, instead of a bare `ValueError` outside the exception hierarchy.
- Client construction and `FieldMask` raise `ConfigError` for empty keys, invalid timeouts and invalid mask paths instead of bare `ValueError`, so every local misuse has the one documented type.
- Default field masks now include the place resource name on every endpoint, and the README and fields docs state plainly that the defaults reach the Enterprise billing tier.
- Header construction fails loudly on a value that cannot be sent instead of silently dropping the header, and an API key that cannot be a header value is rejected when the client is built.
- The offline test stub now honours field masks, returns autocomplete distances only for requests with an origin, and serves photos through a redirect, so the suite asserts the behaviour the real API actually has.

- Release wheels now build on native arm runners (ubuntu-24.04-arm, macos-14) instead of cross runners, with Linux wheels pinned to manylinux 2_28, and the publish job checks the tag against the manifests before uploading to PyPI through trusted publishing.
- Client construction validates the base URL. A base URL carrying a query string or a fragment, or one whose scheme is not http or https, fails at build time instead of silently rerouting every request, while path prefixes keep working and dot segments can no longer escape the configured prefix.
- Client construction also rejects a base URL carrying embedded credentials, which used to become an Authorization header sent to the API host on every request without the caller seeing it.
- The Rust core no longer follows redirects automatically, so the API key header can never be resent to a redirect target. Photo media redirects are followed manually with the API key attached to the first request only.
- Field masks reject duplicate paths, empty segments, wildcard segments and non-ASCII characters, and are bounded at 100 paths and a 4096 character header value.
- The native module rejects timeout values above one hour, the same cap the Python clients document, instead of only the Python layer enforcing it.
- Errors from the Rust core keep their underlying transport or decode cause as a typed source instead of flattening it into message prose.
- Decoded response values are passed through without clamping or range checks, a deliberate posture now stated in the core documentation. The client is a transport and does not hide what the API returned, and request values the caller controls are validated before sending instead.
- The dev profile keeps only line-table debug info, so incremental `maturin develop` builds stay fast, and the release profile is unchanged.
- Response models are now frozen dataclasses, matching `FieldMask`, and each model's `raw` is a deep copy of its payload, excluded from repr and equality, so a shared result cannot be rebound field by field and results compare on their modelled fields. The freeze is shallow, and list fields and the raw payload stay mutable in place. `LatLng` is hashable.
- The default Place Details field mask now requests every modelled field, so a default `place_details` call populates address components, plus code, viewport, postal address and current opening hours instead of leaving them permanently empty, while the search defaults remain a curated subset.
- Printing a `PlacesError` now shows the context the type collects (the failed call, the status code, the Google status and the retry delay) alongside the message.
- `Place.opening_hours` gains the alias `Place.regular_opening_hours`, matching its wire name.
- The README now leads with the prebuilt wheel install story, and building from source moved into a collapsed section.
- Text Search drops its duplicate `max_results` parameter, leaving `page_size` as the one spelling for that endpoint. Nearby Search keeps `max_results`, which maps to its own endpoint's `maxResultCount` field. Passing `max_results` to `text_search` now raises a plain `TypeError`, like any unknown keyword.
- Every GitHub Action in both workflows is pinned to a commit SHA with the resolved version in a trailing comment, including the PyPI publish action, which previously tracked a moving branch. The workflows declare per-job permissions and no longer persist checkout credentials.
- Release builds no longer target the retired macos-13 runner image, which had left the macOS Intel wheel leg unable to start, and the macOS legs now pin their deployment targets, 10.12 for Intel and 11.0 for Apple silicon.
- Publishing is gated on an install matrix that installs and imports every built wheel on its own platform plus the sdist, with a Python 3.10 leg exercising the abi3 floor, and every test install is hermetic, so a job can never silently test the published package instead of the artifact it just built. The publish job runs only on version tag pushes, the tag pattern accepts version tags only, and a publish in flight is never cancelled by a re-run.
- The declared Rust floor is 1.88, the oldest toolchain that compiles the locked dependency set, up from a declared 1.74 that the locked dependencies no longer support. The pin lives in a new `rust-toolchain.toml` and in CI, and Cargo and maturin invocations in the gate and the workflows now run with `--locked` wherever the flag is accepted.
- Package metadata uses the SPDX license expression form, carries project URLs and a Python 3.14 classifier, and aligns the keyword list with the Cargo metadata.
- The source distribution no longer ships the CI configuration under `.github`.

### Fixed

- Error envelopes that arrive on a success HTTP status now raise the typed exception for their Google status on every endpoint, photos included, instead of decoding as empty results or returning the envelope JSON as image bytes.
- Response bodies are read under a size cap, gzipped bodies decompress, and a failed body read keeps both the HTTP status and the read failure in the resulting error instead of dropping one of them.
- Photo downloads are checked against their declared content type and the signature of the format it claims before the bytes can be saved as an image, and photo failures served by an image host after a redirect are worded as image host failures.
- Place ids and photo resource names are validated strictly and percent encoded segment by segment, closing query injection, fragment truncation and path traversal through both values.
- Non-finite timeout values raise `ConfigError` instead of panicking across the FFI boundary, timeouts are bounded at one hour, and numeric arguments such as result counts and photo dimensions are range validated in Python before they reach the core.
- Envelope error messages are capped at 500 characters, `google_status` is `None` rather than an empty string when no envelope status was parsed, server side canonical statuses such as `DEADLINE_EXCEEDED` classify as `ApiError` instead of falling through to the HTTP classes, and truncated non-envelope bodies say they were truncated.
- Exceptions now carry `status_mismatch`, `retryable`, `retry_after` and `context` attributes, model conversion failures raise `DecodeError` instead of escaping as bare builtin exceptions, and unknown top level fields on Autocomplete responses survive into `raw` as they already did on search.
- `page_size` gets the same range validation as the other numeric arguments instead of reaching the API unchecked or leaking an internal conversion error, error envelopes carrying a code or a message but no status string raise the exception their numeric code maps to instead of succeeding silently, and error envelopes on the photo download path raise that mapped exception with its Google status and server message instead of a decode error that dropped both.
- Partial nested response objects decode with defaults instead of failing the entire response, so a location carrying only a latitude, a viewport carrying only one corner, or a circle carrying only a center no longer poisons every place in the result.
- Unknown fields inside nested response objects are preserved into the raw view like top level fields, counts and dimensions that arrive string encoded or as exactly integral floats decode normally, a zero start offset in autocomplete matches survives reserialization, and unknown fields carrying integers beyond 64 bits keep every digit.
- One mistyped field in an error envelope no longer discards the Google status, message and details the rest of the envelope carried, and retryability follows the HTTP status on every error type that carries one instead of only one variant.
- A failed photo request can no longer leak the API key into the exception message through the photo URL, a photo response with no declared image content type is refused instead of being returned as photo bytes, an empty JSON object in the skip redirect photo form is a decode error instead of a photo result pointing at an empty URI, and a failed body read after a success status carries that status on the error instead of losing it.
- Empty optional strings and lists are omitted from request bodies and empty Place Details query parameters are omitted, instead of being sent as empty values whose meaning differs from absence at the API, and a zero response size cap is rejected when the client is built instead of failing every call.
- A request body whose circle omits its center, or whose center omits a latitude or a longitude, fails locally with a configuration error instead of being sent aimed at latitude 0.0 and longitude 0.0, while response decoding keeps its lenient defaults.
- A bare string passed for an iterable of strings parameter (`fields`, `price_levels`, the type and region filters) is rejected with `ConfigError` before any request, instead of being shredded into one-character items and sent. Field masks validate the wire grammar locally, with camelCase segments, no empty segments, whitespace, commas or wildcards, duplicates removed, and set input sorted for a deterministic header.
- Boolean request fields accept only real bools, in the Python body builders and in the Rust conversion layer, so the string "false" can no longer reach the wire as true through any path, including dict shaped routing parameters.
- Coordinates are validated in Python in every slot (nearby location, origins, circle centers, rectangle corners, wire shape dicts). Sets are rejected because their order is arbitrary, bools and strings are not numbers, and NaN, infinity and out of range values raise `ConfigError` before the request is built.
- Local misuse that used to escape as bare builtin exceptions (a non-string API key, place id or query, a list where a location dict belongs, a non-finite radius) now raises `ConfigError` naming the parameter, locally raised errors carry the calling method as their context, and `place_photo` enforces its at-least-one-dimension rule before the native call.
- Calling the sync `Client` from inside a running event loop raises `ConfigError` pointing at `AsyncClient` instead of freezing the loop for the request duration.
- Pickling or copying a client raises a `TypeError` naming placekit and the real reason, instead of an error naming a phantom `builtins.Client` class, and shallow copy no longer silently shares the live native client.
- The shipped type stubs match the runtime, with constructors for `Place` and `PlacePrediction`, optional `fields` on the native methods, `retry_after` as a float, the frozen `FieldMask` dataclass, and `raise_translated` declared with its `NoReturn` type.
- The source distribution no longer ships the repo toolchain pin file, whose component list made rustup roll back its own sync and left source builds without a working cargo. Source builds now follow the manifest Rust version with the toolchain the builder already has, and the pin keeps applying to work inside the repo itself.
- `PhotoUriResult` now carries the full JSON form the photo media endpoint returned on its `raw`, deep copied like the other result raws. The binding previously crossed only the name and the URI, so any field Google adds to that form was dropped outright instead of surviving unmodelled.

## [0.1.0] - 2026-10-28

### Added

- Text Search, Nearby Search, Place Details, Autocomplete, and Place Photos against the Google Places API (New), from a typed Rust core using reqwest with rustls.
- Sync `Client` and `AsyncClient` with identical method sets, backed by one shared Tokio runtime in the bindings.
- Dataclass response models with attribute access, including `Place`, `Photo`, `AutocompleteResult`, and `PhotoMedia` with a `save()` helper.
- Field masks as a typed feature via `FieldMask`, with curated per-endpoint defaults and local validation.
- A typed exception hierarchy (`AuthenticationError`, `RateLimitError`, `NotFoundError`, `InvalidRequestError`, `NetworkError`, `DecodeError`, `ConfigError`) translated from Google error envelopes.
- A `base_url` override on both clients, enabling fully offline testing against a stub server.
- Full type stubs and a `py.typed` marker, abi3 wheels for Python 3.10 and newer, and a GitHub Actions workflow that builds wheels for Linux, macOS, and Windows and publishes tagged releases.
